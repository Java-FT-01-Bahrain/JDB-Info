# Setting up RDS PostgreSQL Database

## Learning Objectives

* Create an RDS PostgreSQL database instance using AWS Console
* Configure database settings within account constraints
* Set up proper connectivity for Spring Boot applications
* Understand security group and VPC configuration

## Setting up RDS

We will create a PostgreSQL database on Amazon RDS to support our Spring Boot application. This database will be
configured with specific constraints including single availability zone deployment, 20GB storage, and db.t4g.micro
instance type.

Navigate to AWS Console → RDS → Create database

## Availability and Durability

The deployment option determines how your database is distributed across availability zones. For cost-effective
development environments, we use single-AZ deployment which provides adequate reliability while keeping costs low.

Select "Single-AZ DB instance deployment (1 instance)"

## Database Settings

The database identifier is a unique name for your RDS instance within your AWS account. We also need to set up the
master user credentials that our Spring Boot application will use to connect to the database.

DB instance identifier: `student-app-database`
Master username: `postgres`
Credentials management: Select "Self managed"
Master password: `YDg3y^^WD2b2bv22`

## Instance Configuration

The instance class determines the CPU and memory resources allocated to your database. Burstable classes are ideal for
applications with variable workloads as they can handle occasional traffic spikes.

DB instance class: Select "Burstable classes (includes t classes)"
Choose `db.t4g.micro`

## Storage Configuration

General Purpose SSD provides a balance of price and performance suitable for most database workloads. The allocated
storage must be set to exactly 20GB to match the account constraints.

Storage type: Keep "General Purpose SSD (gp2)"
Allocated storage: `20` GiB

## Connectivity Configuration

The connectivity settings determine how your database integrates with your AWS network infrastructure. We configure it
to be accessible only within the VPC for security purposes.

Compute resource: Select "Don't connect to an EC2 compute resource"
Network type: Select "IPv4"
Virtual Private Cloud (VPC): Use "Default VPC"
DB subnet group: Select "default"
Public access: Select "No"
VPC security group: Select "Choose existing" and use "default"

## Additional Database Configuration

After setting the basic database configuration, you need to expand the "Additional configuration" section to create the
actual database that your application will use.

Initial database name: `studentdb`

This creates the PostgreSQL database inside your RDS instance that your Spring Boot application will connect to. This is
different from the instance identifier and is required for your application to work properly.

## Summary

Your RDS PostgreSQL database is now configured with single-AZ deployment, 20GB storage, and proper network security. The
database will be accessible only from within your VPC, making it secure for your Spring Boot application deployment.

# Setting up Elastic Beanstalk for Spring Boot Application

## Learning Objectives

* Deploy a Spring Boot application using AWS Elastic Beanstalk
* Configure environment settings for database connectivity
* Set up proper platform and instance configuration
* Connect the application to the RDS database

## Setting up Elastic Beanstalk

Elastic Beanstalk simplifies the deployment and management of web applications on AWS. It handles the infrastructure
provisioning, load balancing, and scaling while you focus on your application code.

Navigate to AWS Console → Elastic Beanstalk → Create application

## Environment Tier

Elastic Beanstalk offers different environment types to support various application architectures. Web server
environments handle HTTP requests and are ideal for web applications and APIs.

Select "Web server environment"

## Application Information

The application name serves as a container for all environments and versions of your application. This name will be used
across all related AWS resources.

Application name: `springboot-api`

## Environment Information

The environment represents a specific deployment of your application with its own URL and configuration. Environment
names must be unique within your region and cannot be changed after creation.

Environment name: `springboot-api-env`
Domain: Leave blank for autogenerated value (will become something
like `springboot-api-env.us-east-1.elasticbeanstalk.com`)

## Platform Configuration

The platform determines the runtime environment for your application. Corretto 21 is Amazon's distribution of OpenJDK
and provides excellent performance for Spring Boot applications.

Platform: Select "Java"
Platform branch: Select "Corretto 21 running on 64bit Amazon Linux 2023"
Platform version: Select "4.7.0 (Recommended)"

## Application Code

You need to upload your compiled Spring Boot JAR file. Make sure you have built your application first using Maven.

Build your application first: `./mvnw clean package -DskipTests`

Select "Upload your code"
Version label: `v1`
Source code origin: Select "Local file"
Choose file: Select your JAR file `demo-0.0.1-SNAPSHOT.jar`


## Configure service access

To configure service access for Elastic Beanstalk, you'll need to set up IAM roles and EC2 instance profiles that allow 
Elastic Beanstalk to create and manage your environment. Both the IAM role and instance profile must be attached to IAM 
managed policies containing the required permissions.

- Service access
  - Click "Create role" under Service role
  - Select "AWS service" as the trusted entity type
  - Choose "Elastic Beanstalk" from the Service or use case dropdown
  - Select "Elastic Beanstalk - Environment" as the use case
  - Click "Next"
  - Review the permissions policies (AWSElasticBeanstalkEnhancedHealth and AWSElasticBeanstalkManagedUpdatesCustomerRolePolicy will be automatically attached)
  - Click "Next"
  - Click "Create role"
  - Return to the Configure service access page
  - Select the newly created role `aws-elasticbeanstalk-service-role` from the Service role dropdown
- EC2 instance profile
  - Click "Create role" under EC2 instance profile
  - Complete the EC2 instance profile creation (following similar steps)
  - Select the EC2 instance profile `aws-elasticbeanstalk-ec2-role` from the dropdown
  - Continue with your Elastic Beanstalk environment setup

## Networking Configuration

The networking settings determine which VPC and subnets your Elastic Beanstalk environment will use. It's crucial that
your application runs in the same VPC as your RDS database to enable communication between them.

VPC: Keep the default VPC (same as your RDS database)
Public IP address: Leave "Enable" unchecked for better security
Instance subnets: Select at least one subnet, such as:

- `us-east-1a`
- `us-east-1b`

## Database Integration

Elastic Beanstalk can create and manage a database for your environment, but since you already have an RDS database, you
should skip this option to avoid creating duplicate resources.

Database: Leave "Enable database" unchecked (you will connect to your existing RDS database)

## Environment Properties

Environment variables allow your Spring Boot application to connect to external services like your RDS database. These
variables are injected into your application at runtime.

Configure the following environment variables with your specific RDS database information:

Name: `SERVER_PORT`, Value: `5000`
Name: `SPRING_PROFILES_ACTIVE`, Value: `prod`
Name: `RDS_HOSTNAME`, Value: `[your-rds-endpoint]` (get from RDS console)
Name: `RDS_PORT`, Value: `5432`
Name: `RDS_DB_NAME`, Value: `studentdb`
Name: `RDS_USERNAME`, Value: `postgres`
Name: `RDS_PASSWORD`, Value: `[your-database-password]`

To get your RDS endpoint:

1. Go to RDS console
2. Click on your database `student-app-database`
3. Copy the endpoint from the Connectivity section
4. Update the `RDS_HOSTNAME` value with this endpoint

## Final Steps

After configuring all environment variables, proceed to create your environment.

Click "Next" to review your configuration
Click "Create" to deploy your environment
Wait 5-10 minutes for environment creation to complete

## Summary

Your Elastic Beanstalk application is fully configured with Java platform, single instance deployment, proper IAM roles,
network settings matching your RDS database VPC, and environment variables for database connectivity. The environment
creation process will provision the necessary AWS resources and deploy your Spring Boot application with database
connectivity.
